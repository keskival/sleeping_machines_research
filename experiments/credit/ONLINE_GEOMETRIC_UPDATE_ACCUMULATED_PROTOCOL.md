# R1 forward-trained update function: fixed-version feedback aggregation

Decision: does averaging sixteen causal next-target meta-gradients improve prequential loss relative to freezing the identical pretrained function? This follows the completed first-stage utility failure; it is not selection on public DEV/TEST.

Retain the first-stage native source, block curvature, 25,027-parameter function, meta Adam .001, step cap .08 and four diagnostic arms. Repeat the 1,024-target TRAIN pretraining at source training tokens +720896, disclosed reuse. Four new private TRAIN-tail episodes start at +851968 +1024*i, each with 64 context and 512 scored targets. Smoke uses +858112, two 32-target episodes and 64-target pretraining. Initialization seed 99710. Primary paired episode-bootstrap95 lower gain bound above zero versus the frozen pretrained function. All costs, including repeated pretraining, are charged.

One pending differentiable update receives the next target gradient and is released. Accumulate parameter gradients at the unchanged function version for sixteen valid feedbacks, divide by their count, then commit Adam. Numerical learner state continues evolving between feedbacks but incoming state is detached for each issued update. EOS discards pending graphs and resets fast state while preserving already observed gradient buffers. End of phase discards unused pending graph and flushes the partial batch before checkpointing. Record feedback count and optimizer update count separately. Frozen function is context dependent but never fitted during its episode.

Contract: exact accumulated mean of individually issued derivatives, commit/version boundaries, EOS reset, final partial flush and stale-version rejection. Retained graph storage stays one update. Averaging trades response latency against gradient noise; no independent-sample assumption. This is a restricted lexical-head diagnostic, not full native/optional-route learning, a depth scaling result, or hardware efficiency evidence. Native forward and all arms, basis, solver, optimizer and supported operation accounting follow the first-stage protocol.
