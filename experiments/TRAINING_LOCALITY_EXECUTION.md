## Readiness invariant

For bank b at declared version v and credit event e, the issuer declares the complete producer set P_b. The update is allowed only after each producer supplies exactly one same-version contribution, summed in a fixed canonical order. A complete bank may update without waiting for another bank whose P differs. The actor still needs an explicit read-consistency policy. Parameter-version tags do not make gradients from mixed undeclared snapshots correct.

Canonical sum order is needed for reproducible floating-point arithmetic. The initial inbox retains each fragment until completion; memory is O(sum_b |P_b| * bank_gradient_size), plus producer metadata and duplicate tracking. This is a correctness implementation, not a proven memory optimization. A deterministic causal merge tree or bounded accumulator requires its own arithmetic/work contract. Missing, repeated, stale and overflowed credit is rejected, never silently converted to zero.
