# Local credit depends on more than the receiving bank's version

13October2026. R1/B10 native update enabler, following EVENT_LOCAL_CREDIT_AND_VERSIONED_UPDATE_BANKS.md. The existing final-gradient banks reject a packet whose own target version moved. That is sufficient for reproducing a pre-issued synchronous/Jacobi update endpoint with frozen final gradients. It is not a complete test of whether a delayed gradient is current during interleaved prediction and updates: an upstream producer, scored key, shared readout or observed memory can move while the receiving parameter stays fixed.

Let a credit target be F_e(theta_D,s_S), with declared complete parameter read set D and state read set S, and receiving bank b∈D. A packet carries g_b, event/target lineage, and issued stamps {(j,v_j):j∈D}, {(k,u_k):k∈S}. Strict current-context delivery requires equality of every declared stamp, plus the bank's gradient schema and exactly-once bank-version rule. There is no global epoch: changes outside D/S do not invalidate this declared target. Read-set completeness is part of the contract, not inferred from packet size. Alternative-route/future-loss targets may have broader dependencies than the factual active route.

This establishes validity for the named computation and sampled target, not the unknown current population risk. For risk R_b with explicit block-gradient sensitivity bounds H_bj and state sensitivity K_bk, an issued credit error obeys

    ||e_b,current|| ≤ ||e_b,issued|| + Σ_j H_bj||Δtheta_j|| + Σ_k K_bk||Δs_k|| + V_b.

V_b includes changed future-risk distribution and, if completeness is only approximate, omitted-dependency effects. Exact stamp matching makes the tracked displacement terms zero; it does not remove approximation or distribution shift. When Adam maps credit to a proposal d_b, evaluate alignment and actual future utility in that proposal's metric, as in the existing local-bank theory. A learned bounded-staleness policy must be trained on real acceptance/update outcomes with residual audits; strict rejection remains the reference policy. No additional tower of trainers is required by recording these observed outcomes and exact forward/version anchors.

DependencyBankDelivery implements strict sparse stamp checking and tracks local state-write versions. Binary-layout projection uses32-bit addresses,64-bit versions/event/target IDs and two32-bit read counts. A packet with2parameter/1state dependencies costs72metadata bytes plus its gradient payload before link framing, fanout, routing and handshake. This can dominate tiny gradient packets, so source/consumer placement, canonical shared-bank ownership and safe aggregation must be evaluated quantitatively. Python object sizes are not hardware wire bytes.

Queued delivery contract: a producer update with the receiving bank unchanged is rejected; a relevant memory write is rejected; declared unrelated bank/state progress permits delivery; replay after acceptance is rejected. It does not yet infer native actor dependency sets or change current training. The next integrated test must derive the read set from actual factual/counterfactual computation and record accepts/rejects, retries, packet bytes and numerical/quality effects under interleaved events. Preserve Curie's existing native eligibility and update pipeline.

Concurrency boundary: this prototype uses serialized message delivery and tests interleavings at event boundaries. It does not supply a distributed atomic read-set snapshot. Actual concurrent silicon needs dependency leases/commit-time revalidation or a bounded-movement acceptance rule, with coherence/handshake work charged. Per-bank version checking alone must not be advertised as solving that problem.
