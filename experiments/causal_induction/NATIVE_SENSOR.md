# Integrated sensor interface: diagnostic before structural acquisition

B5/R1 development, 12 October 2026. The failure addressed is concrete: the market boundary-credit rules have not improved complete learning against native BPTT, and the affine circuit data have no integrated learner yet. A new task-specific sensor interface tests whether the retained substrate can use observed cross-node information before adding a learned-credit objective.

The actor reuses AddressedEventHeads: two temporal layers, two independent race heads, two receiver alternatives, eight values per head, separate keys/values, decaying/rotating persistent memory and hard selected writes. One shared parameter bank acts on independent addressed node states. Public node IDs select numerical state, never embeddings or supervised ancestry. Receiver training retains the existing local counterfactual surrogate and charges all receiver proposals; inference proposes only winners. No core implementation or completed driver is modified.

At a future-bit request, the target node and up to seven distinct recently observed nodes form the discovery set. Shared key/query functions score their evolved contexts; an exponential race selects one source context. The binary sensor combines target/source context with publicly known bits, elapsed ages and requested horizon. One uniformly sampled nonwinner is decoded during training. Later feedback supplies its actual loss difference, and the existing paired-route surrogate trains the choice probabilities. The binary outcome is observed supervised feedback, not a gradient-imitation target or hidden generator label.

This is a bounded sensor-read route, not learned inter-node event delivery. Node states currently evolve independently between observations; the critic and optional event routes are subsequent integration work. Temporal unit delays still perform computation and persistent states support future reads. A sensor reads only states produced by observations already received. If computational arrival exceeds physical query time, read alignment uses the later computational time: latency is a model cost, not permission to use future observations. Arbitrary unobserved simulator messages never enter the actor.

The guarded contract checks exact address-renaming invariance under common randomness, causal issued forecasts/feedback and actual temporal-unit parameter learning. Optimizer changes happen only after feedback, with no pending differentiable forecasts; persistent numerical state survives gradient truncation. The private first fit uses eight TRAIN graphs, two passes and four distinct development graphs, comparing the identical actor with self-only versus cross-source sensor reads. This is an interface/headroom diagnosis. A useful result requires improvement over public-stream persistence as well as a favorable comparison between the two native arms. Neither a first-pass failure nor a small affine-data success is a verdict on the family.

Count candidate keys, delivered source values, sensor decodes, selected receiver writes, losing receiver proposals and optimizer updates; record complete fitting and development CPU, pipeline wall and peak RSS. These counts are not a full FLOP audit. Broader root factors/nonlinear mechanisms, unseen deeper graph tests and learned connected route-credit comparisons follow this integration stage; no new Transformer/LSTM reference fitting or public TEST is admitted.

Accounting interpretation for v1: `value_reads` counts contexts delivered to sensor decodes, not all persistent-value traffic. The source key path evolves every candidate context. Each query therefore performs `candidate_keys + 1` context reads/transports, including the target read, before winner/alternative decoding. All these accesses belong to discovery work. Do not use the selected-read counter as a memory-traffic or winner-only key-discovery claim. A later driver uses an explicit discovery-read counter.
